# BF16 SSM state on the merged MXFP8 profiles — 2026-10-12

These measurements compare the merged profile with ordered FP32 GDN against the same profile with BF16 SSM state and native vLLM GDN. The pinned SM120 FlashInfer fused GDN decode rejects BF16 state, so BF16 uses the FLA packed recurrent decode fallback. This is a comparison of complete configurations, not an isolated dtype-only ablation. FP32 remains the launcher default.

## Throughput

RTX 5090, TP1; 2B on GPU0 and 4B on GPU1. Each model ran BF16 then FP32 sequentially on the same GPU, once per configuration, with automatic clocks. Other GPU jobs were active on this shared host. Each point uses 3,000 input tokens and 1,000 output tokens; concurrency 4/16/24/32/48/64 uses 40/160/120/160/240/320 scored requests. All 1,040 requests per configuration succeeded. JIT, prewarm and internal warmup are excluded. Pooled throughput is total output tokens divided by the sum of scored durations. Single-run differences have no statistical confidence interval.

Both configurations retain the merged MXFP8 projections, fused SwiGLU quantization, M≤64 candidate/refinement head and graph policy. 2B retains Triton attention/BF16 KV; 4B retains FlashInfer attention/calibrated FP8 KV and BA/QKVZ overlap. The production KV budget is 19 GiB.

FP8 figures come from retained historical baselines: [2B](data/mxfp8-2b-triton-hybrid-sixpoint-20261011.json) and [4B](data/mxfp8-qualification-20261006.json). FP8 was not rerun in this experiment. The 2B baseline uses GPU1 per-point medians versus current GPU0, so this is a descriptive cross-card comparison. Historical pooled throughput below is reconstructed with the same request weights as the current six-point workload; it is not a separately observed pooled run. Gains are `(merged throughput / historical FP8 throughput - 1) × 100%`. FP32 and BF16 below refer to SSM state in the merged MXFP8 profile.

## Numerical fidelity

Each run teacher-forces the same 256 frozen queries and scores 10,479 gold-token raw logprobs, with 64 queries each in Chinese, English, code and math. MAE and maximum absolute error are measured against frozen BF16-model records, not task accuracy. 2B uses its fixed BF16 M32 anchor for both row counts; 4B uses the corresponding BF16 M32/M64 anchor. Each comparison has freshly measured FP32 and BF16 state runs on the same GPU (2B GPU4, 4B GPU5). 2B uses a 4 GiB KV budget at both row counts; 4B uses 4 GiB at M32 and 19 GiB at M64, in separate fixed-row precision profiles.

| Model / rows | FP32 MAE | BF16 MAE | MAE change | FP32 max error | BF16 max error |
|---|---:|---:|---:|---:|---:|
| 2b-m32 | 0.048650819 | 0.048677361 | +0.055% | 1.539302 | 1.282413 |
| 2b-m64 | 0.049183463 | 0.049636202 | +0.921% | 1.202668 | 1.099077 |
| 4b-m32 | 0.049038113 | 0.049382484 | +0.702% | 2.757282 | 2.560960 |
| 4b-m64 | 0.053286047 | 0.053009216 | -0.520% | 1.859963 | 2.316581 |

At 4B M64, the lower mean error accompanies a higher maximum error (1.859963 → 2.316581). BF16 is an optional throughput tradeoff, with FP32 retained as the default. All first-cohort repeats were bitwise identical in raw logprobs. The compact-head audit found zero top1 differences against the complete head on the same hidden states in every run; audit counts include padding and repeats. This does not establish identical free-running generations between FP32 and BF16 state. These fixtures do not qualify long-context recurrent-state accumulation.

## Activation and verification

Append `--ssm-dtype bfloat16` to either existing launcher command. The equivalent alias is `--mamba-ssm-cache-dtype bfloat16`. Omit the flag or use `--ssm-dtype float32` for the default ordered path. Worker receipts validated actual BF16 CUDA state tensors in all 18 (2B) or 24 (4B) recurrent layers, with no ordered hooks or ordered scratch allocation. All expected precision FULL graph sizes were captured.

CPU regression: 535 passed, 105 skipped, 1 deselected, 84 subtests passed. The deselected MXFP6 MoE test requires a visible CUDA GPU and is outside this SSM change; it fails CUDA initialization in the CPU-only environment. GPU validation is the complete serving and teacher-forced matrix above. The final cleanup selects the GDN backend once during worker registration; inference kernels are unchanged, and the CPU regression was rerun after cleanup.

[Machine-readable measurements and artifact hashes](data/mxfp8-bf16-ssm-20261012.json) include per-domain precision, receipt summaries and measured-source fingerprints. Local raw artifacts and reproduction drivers are under `/data/lxy/detailed_benchmark/mxfp8-bf16-ssm-20261012`. Private fixture texts and token records are not copied into the repository.
