# Qwen3.5-2B MXFP8 TP1 measurements — 2026-10-10

The current branch now applies fused SwiGLU/MXFP8 down projection to the 2B MLP geometry, alongside the existing 4B support. The checkpoint/KV/SSM comparisons below use this same implementation.

[Machine-readable results](data/mxfp8-2b-20261010.json) include exact throughput, latency, numerical-error metrics, workload seeds, checkpoint fingerprints and validation results.

## Runtime and workload

One RTX 5090, TP1; vLLM 0.29.0, PyTorch 2.13.0+cu130, FlashInfer 0.6.18. Current base commit `9c73336d4d67`; main reference `e4a4e594bf3f`.

The current profile uses BF16 activations, native MXFP8, PDL for eligible decode rows, fused Gemma RMSNorm and MLP, Triton attention, CUDA Graphs, chunked prefill, 128 maximum sequences, 8192 maximum model length, 4096 maximum batched tokens and 0.85 GPU memory utilization. TP1 Mach GDN is disabled; recurrent decode uses the stock CUDA kernel. The hybrid LM head uses 128 NVFP4 search candidates and BF16 refinement for at most 32 rows; unsupported requests fall back to the full BF16 head. Prefix caching and speculative decoding are disabled.

Serving uses the same protocol as the 4B comparison: 3000 input / 1000 output tokens, uniform token IDs, greedy streaming requests, and concurrency 4/16/24/32/48/64 with 40/160/120/160/240/320 scored requests. Every checkpoint/configuration completed all 1040 requests and 1,040,000 output tokens. Startup and warmup are excluded. Pooled throughput is total output tokens divided by the sum of scored durations, not a mean of per-point rates.

`main` denotes the BF16AttentionEnds rebuilt checkpoint; `original` denotes the original MXFP8 checkpoint. They share 405 identical tensors. Main stores 33 weights in BF16 where original uses MXFP8 and has 33 corresponding additional scale tensors: full-attention projections, first-layer GDN projections/MLP, and last-layer MLP. Embeddings and BF16 LM head match. Verified native linear / fused norm / fused MLP counts are 78/61/22 for main and 96/61/24 for original.

## Numerical fidelity

The metric matches the latest main 2B evaluation: token-weighted gold-token **raw-logprob MAE** against its frozen BF16 reference, lower is better. The `production-per-request-fixed-token-v1` replay uses cohort 32, 256 queries (64 each in math, code, English and Chinese), and 10,479 gold tokens. Current replay uses a fixed 16 GiB KV budget and one CPU thread rather than the serving memory/thread settings. Raw-logprob requests use the full BF16 head; hybrid top1 is probed separately on identical teacher-forced hidden states.

| Runtime / checkpoint | KV | SSM | MAE | P99 absolute error | Maximum absolute error |
|---|---|---|---:|---:|---:|
| Main / main | BF16 | FP32 | 0.04822663 | 0.391718 | 1.012241 |
| Current / main | bfloat16 | float32 | 0.04903855 | 0.389901 | 2.191884 |
| Current / main | fp8_e4m3 | float32 | 0.05090945 | 0.416796 | 1.598728 |
| Current / main | bfloat16 | bfloat16 | 0.04924842 | 0.395697 | 1.456040 |
| Current / original | bfloat16 | float32 | 0.05902682 | 0.478762 | 1.733890 |
| Current / original | fp8_e4m3 | float32 | 0.06082298 | 0.495523 | 1.838905 |
| Current / original | bfloat16 | bfloat16 | 0.05820758 | 0.456175 | 1.087932 |

Every current configuration scored all 10,479 gold tokens, repeated the first cohort with zero raw-logprob difference, and matched the full BF16 head top1 at all 10,479 probed states. This measures numerical fidelity, not downstream task accuracy or free-running generation equivalence. Turning FP8 KV off lowers average error but increases main-checkpoint maximum error (1.5987 to 2.1919); BF16 SSM then lowers that maximum to 1.4560.

## Main and current optimization profiles

Both use native SM120 MXFP8 W8A8 kernels and CUDA Graphs with BF16 activations. Main's production profile uses ordered FP32 GDN window-4 updates, mixed decode batches 24–160 and BF16 BA GEMV for 1–8 rows, pinned asynchronous reset-ID uploads, FlashAttention 2, full BF16 head, BF16 KV, FP32 SSM, maximum sequences/length/batched tokens 160/16384/2048, and a fixed 19 GiB KV budget. Its graphs capture 4/8/16/24/32/48/64/96/128/160 plus the 2048 piecewise prefill boundary. Window-4 denotes an update window, not four-bit state quantization.

The current profile adds eligible PDL, fused Gemma norm/SwiGLU-MXFP8 paths and hybrid head search, with stock CUDA GDN, Triton attention and the scheduler settings above. The baseline state remains FP32; the BF16 SSM experiment verifies actual BF16 CUDA state tensors in all 18 recurrent layers. Both the checkpoint format and the runtime profile affect main-versus-current fidelity, so the same-main-weights row is the relevant runtime comparison.
