# 0.1.0a5

Three opt-in additions for the Qwen3.8-27B Dense, vLLM 0.28, SM120 TP2 profile:

- Load original MXFP6 checkpoint weights without requantizing EXL3 weights. Merge QKV/QKVZ execution at physical M32 and prefill M>=128.
- Add a separately built Temporal M24 K6 kernel for the two validated QKV/QKVZ bundle shapes. Enable with `EXL3_TEMPORAL_QKV_M24=1`, BF16 I/O and M24 support. It defaults to off; missing native builds fall back to the existing BF16 path.
- Reject prebuilt FlashInfer communication modules that bypass the MXFP8 scale-layout patch. The supported 0.6.18 source build requires the matching patch and no prebuilt communication cache.

The ExLlamaV3 1.4.8 BF16 source profile is included. Default dependency pins and existing execution switches are unchanged. Native wheels must be built against the serving environment; they are not included in the Python wheel.

Validation: 115 package tests passed, 3 skipped. Real-weight eager and changing-input Graph outputs matched the frozen Temporal implementation on both ranks for both bundle types. The combined TP2 service captured seven Graph sizes and passed 40/40 tasks at concurrency 24, with zero regressions and 33/40 exact reference outputs.

Temporal M24 changes the EXL3 reduction order. The source experiment showed workload-dependent gains and regressions; this release does not claim bitwise equivalence to the previous EXL3 kernel, full-model losslessness, or a new end-to-end speedup. Private FLA tuning is not included.
