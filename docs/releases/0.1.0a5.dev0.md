# 0.1.0a5.dev0 — development candidate

Not a published release. The validated installation remains at 0.1.0a4.

## Changes

- Add the opt-in `qwen38-27b-checkpoint` hybrid profile. It reads original MXFP6 packed weights and scales, preserving rank-local slicing without reconstructing or requantizing EXL3 weights.
- Merge QKV/QKVZ execution at physical M=32 and M>=128. Other QKV row counts retain EXL3. MLP and attention output projections use MXFP6; the existing hybrid profile remains available unchanged.
- Validate source quantization metadata, model geometry, tensor shapes, and TP shard order. Require an explicit paired local checkpoint.
- Prepare an ExLlamaV3 1.4.8 source patch carrying the BF16 APIs from upstream PR #330. The validated dependency pin is unchanged.

See [configuration and limitations](../checkpoint-hybrid.md) and the [native upgrade candidate](../../profiles/exllamav3-1.4.8/README.md).

## Validation

The fused collective header check is unchanged. A different FlashInfer 0.6.18 header failed a local compatibility experiment and remains rejected. The profile documentation corrects the version-only compatibility claim and adds a preflight check before service startup.

CPU-only tests in the official vLLM 0.28.0 image: 95 passed, 3 skipped. All 512 rank-local projections matched the frozen source converter byte-for-byte, including logical scales and both service content digests. ExLlamaV3 1.4.8 with the BF16 patch built successfully using CUDA 13.2. The real-weight native check passed 52 cases across both ranks, with three changing inputs per case and bitwise agreement between eager execution, Graph replay, and the reference call paths.

TP2 service results and runtime limitations are recorded in [validation.md](../validation.md). Temporal M24 and private FLA tuning patches are not included. Experimental throughput and fidelity results are not measurements of this Mach build; a full-model fidelity and performance comparison remains separate release work.
