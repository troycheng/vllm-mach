# v0.1.1

v0.1.1 adds native MXFP6 inference for Qwen3.8-27B Dense and
Qwen3.5-35B-A3B MoE on vLLM 0.29.0. The validated deployment uses Linux
x86-64, Python 3.12 and two RTX 5090 GPUs with TP2/PP1, BF16 activations
and KV, and text-only, non-speculative inference.

## Changes since v0.1.0a10

- Make native MXFP6 the current installation profile, with model-specific
  compilation and CUDA Graph settings, fused AllReduce/residual/RMSNorm,
  and optimized GDN decode.
- Enable Dense lossless and owner prefill by default, support variable SM
  counts in owner prefill, and add exact fused SwiGLU/GDN producers and
  AR/RMSNorm/MXFP8 fusion with the pinned native dependencies.
- Add Qwen3.5 MoE integration and 37 measured non-expert projection dispatch
  configurations, with eligibility and native ABI checks before graph capture.
  Preserve MoE outputs; the compact/fused expert experiment is excluded.
- Provide optional FP16 recurrent state and an NVFP4 LM-head candidate search
  with BF16 refinement through `--fp16-ssm --nvfp4-lm-head`.
- Complete the Docker CUDA Toolkit 13.0 build environment and installation
  instructions, including native dependencies and runtime patches.
- Accept local build suffixes for the supported MXFP6 runtime during plugin
  registration, matching the installer, and check Mach's source and package
  versions for consistency in the deployment tests.
- Publish Dense and MoE throughput, numerical fidelity, and per-optimization
  results with workload settings and sanitized measurement data.

## Recorded validation

The release wheel passed all 314 configured tests on September 28, 2026,
with no failures or skips: eight NVFP4 LM-head tests and 306 remaining tests.
Checks used an isolated Python 3.12 environment with the official vLLM 0.29.0
and FlashInfer 0.6.18 packages, all Mach runtime patches, and two RTX 5090
GPUs. MXFP6 was rebuilt at the pinned revision together with all three Dense
native extensions using CUDA Toolkit 13.0. The installer passed dependency
and native-operation checks, and repeated patch installation reported no changes.
An additional NVFP4 autotune smoke check passed at rows 1, 4 and 32 and
confirmed that the temporary CUDA delay replacement was restored afterward.

At 3,000 input / 1,000 output tokens and c4/c16/c24/c32, the documented
serving profiles show mean throughput gains over their stock FP8 baselines
of 34.0% / 42.7% for Dense default/full and 58.3% / 69.4% for MoE
default/full. These are arithmetic means of per-concurrency gains from the
recorded September 2026 measurements, not new benchmarks of this release.
Dense measurements are short single runs; MoE points are two-run means.

The separate MoE projection comparison completed 1,920 scored requests at
c32/c64/c96/c128/c160. All 960 matched response text hashes agreed, and
31,437 frozen gold raw logprobs matched the baseline at physical
M32/M128/M160. Observed throughput changes ranged from +0.12% to +0.96%
over the prior Mach runtime; these paired observations do not establish
statistical confidence intervals or universal bitwise equivalence.

See the [serving results](https://github.com/troycheng/vllm-mach/blob/v0.1.1/README.md#performance),
[fidelity methodology](https://github.com/troycheng/vllm-mach/blob/v0.1.1/docs/profile-fidelity-20260917.md),
and [MoE projection validation](https://github.com/troycheng/vllm-mach/blob/v0.1.1/docs/moe-projection-20260923.md).

## Installation and limitations

Follow the [installation guide](https://github.com/troycheng/vllm-mach/blob/v0.1.1/docs/installation.md)
or build `deploy/Dockerfile` from the `v0.1.1` source tree. The Python wheel
alone is insufficient: use the pinned MXFP6/CUTLASS sources, build the
required native extensions, and install Mach's runtime patches together.
Earlier EXL3 profiles are retained as historical material.

Mach remains an alpha integration with model, shape, and request constraints.
Broader model-quality and long-context validation remain outstanding. The
full profile changes numerical behavior; fidelity scores do not establish
task accuracy. This release does not change native extension package versions.
